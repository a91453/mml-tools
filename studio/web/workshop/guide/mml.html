MML 是什麼

MML（Music Macro Language，音樂巨集語言）是用純文字寫樂譜的方法。瑪奇 Mobile 的作曲系統吃的就是這種文字——一串像 t120o4l4cdefg 的字，每個角色一串，角色就照著演奏。

它不是五線譜也不是簡譜，比較接近「把每個音怎麼彈寫成指令」。好處是可以複製貼上、可以用文字工具處理；壞處是寫錯了不一定有人提醒你，通常要播出來才知道。

底下的範例都可以貼進工作坊，按「▶ 演奏」試聽（要先在「設定」裡載入自己的音色庫，工作坊不附音色庫；聽到的是 GM 音色近似，不是遊戲音色）。建議一邊看一邊改，聽得到差別比讀得懂更重要。

工作坊裡編輯的一切都標示為「工作坊編輯（未經 Studio 驗證）」。工作坊播得出來、沒有警告，都不代表譜符合 Canonical 規則，也不代表遊戲裡能用。要檢查，請按「送回 Studio 驗證」，由 Studio 重新做技術驗證與審核。

音符與休止符

七個音名對應到 Do 到 Si：

寫法音寫法音
cDogSol
dReaLa
eMibSi
fFar休止符（不發聲）

升記號用 +，降記號用 -，寫在音名後面、長度前面：

c+   Do 升（等於 Re 降）
  d-   Re 降

大小寫都可以，工作坊與 Studio 的解析器都把大小寫當成同一個字。

工作坊專用：工作坊也接受 # 當升記號、連續好幾個升降記號（例如 c++）、h（當成 b）與 p（當成休止符 r）。這些是從其他工具帶進來的寫法，Studio 的解析器只接受一個升降記號，也不認得 h 與 p；按「送回 Studio 驗證」時工作坊會把它們改寫成 +、單一拼法、b 與 r。詳見寫法差異。

長度與附點

音名後面接數字就是那個音的長度，數字是分母：

寫法意思
c1全音符
c2二分音符
c4四分音符
c8八分音符
c16十六分音符
c32三十二分音符
c64六十四分音符

每個音都寫數字很囉唆，所以有 l（length）可以設預設長度——後面沒寫數字的音與休止符都用它：

l8cdefg      跟 c8d8e8f8g8 完全一樣
  l8cde4fg     只有 e 是四分音符，其餘八分

長度數字的範圍（MOBILE_SYNTAX §3）：官方文件寫的音符／休止符長度數值範圍是 1–64，並沒有說只能用 2 的次方。所以：

  • 1–64 之間的長度，不能只因為「不是 2 的次方」就說遊戲不吃；64 在官方範圍內，48 也不是官方禁止的寫法。
  • 專案的 Final 輸出偏好 1／2／4／8／16／32／64（能精確表達節奏時）；其他整數長度（包括 3、6、12、24、48）屬於「謹慎使用」：只在來源節奏需要、而且驗證確認沒有時間漂移時才用。
  • 這些非 2 次方長度在遊戲裡長時間播放會不會漂移，仍待實機測試（PENDING P4）。

後面加一個點是附點，長度變 1.5 倍：

c4.   四分音符 × 1.5（一拍半）
  c8.   八分音符 × 1.5

附點的規則（MOBILE_SYNTAX §4）：專案 Final 的安全時間解析度是 1/64。

  • 偏好：在 1、2、4、8、16、32 上加單一個附點，而且能保留原本的節奏。
  • Final 禁止：64.；3.、6.、12.、24.、48. 這類不穩定的附點；以及上面偏好清單以外的任何附點底數。
  • Final 禁止：雙附點或多附點，例如 1..、2..、4..、8..。
  • 要表達這些長度時，改寫成時間完全相等的「音符＋連結線＋休止符」組合，例如 c4..（1.75 拍）寫成 c4&c8.。
  • 這些被禁止的寫法遊戲引擎本身吃不吃，是另一個仍待實機驗證的問題（PENDING P5）；禁止的是專案的 Final 輸出，不是在宣稱遊戲的行為。

工作坊專用：工作坊的解析器比 Final 規則寬鬆：

  • 它讀得懂雙附點（c4.. 是 1.75 倍），也讀得懂帶附點的預設長度。在工作坊裡，附點是吃在長度數字上的，不會疊加：寫了 l4. 之後，單寫 c 是 1.5 拍，接著的 c. 也是 1.5 拍而不是 2.25 拍。Studio 的解析器不接受 l4. 這種寫法。
  • 「剪貼簿」→「複製」與「送回 Studio 驗證」都會先把 .. 改寫成單附點加連結線的等長寫法；送回 Studio 時 lN. 會改成 lN，原本靠它的音會寫出完整長度。
  • 鋼琴捲軸的「加上附點」只允許全／2分／4分／8分／16分／32分音符（64 分不行），跟上面的偏好清單一致。
  • 工作坊以每拍 480 tick 計時，長度換成 tick 時會取整數，所以 5、7、9 這類分母在工作坊裡播的是近似值。
  • 工作坊把 1、2、3、4、6、8、12、16、24、32、48、64 以外的分母標成「非標準時值」，訊息寫著「瑪奇 Mobile 不吃」，並提供工具列的「還原」把它們換成標準時值。這是工作坊自己的分類：照 MOBILE_SYNTAX §3，1–64 之間的長度都在官方範圍內，不能說成遊戲的禁令。反過來，工作坊當成「標準」的 3、6、12、24、48 在 Canonical 裡屬於「謹慎使用」，它們的附點形式在 Final 裡是禁止的。

八度與音高範圍

o 後面接數字決定接下來的音在哪個八度，例如 o4c。

< 降一個八度、> 升一個八度——旋律上下跑的時候用這兩個比一直寫 o 短很多：

o4cde>c    最後那個 c 高一個八度

Studio 的解析器要求第一個音名之前一定要先寫 o，所以建議每個角色一開頭就寫好八度。

音高範圍（MOBILE_SYNTAX §6）：官方文件寫的是音高範圍 0–107，而不是某一組 o 的範圍。程式裡任何「八度寫得到哪裡」的範圍都只是實作上的對應，必須拿 0–107 的音高模型驗證；o、音名、數字音高與邊界音之間的精確關係還沒有文件化或測試（PENDING P6）。

工作坊專用：工作坊與 Studio 在程式內部都把 o4c 算成 MIDI 60（一般說的中央 C），但這只是兩個程式的換算方式，它和官方 0–107 的精確對應仍待驗證。工作坊的鋼琴捲軸範圍是 o1c–o7b：超出這個範圍的音，工作坊會以八度為單位摺回範圍內播放，並在狀態列警告「有音高超出捲軸的 o1c–o7b，已折八度塞進來」。Studio 目前的實作對應是 O0–O8，並對換算後超過 107 的音名提出警告。

速度：每個角色都帶同一張速度表

t 後面接數字設定速度（BPM），例如 t120。遊戲作曲編輯器的速度輸入範圍是 32–255，這是官方確認的範圍，也是專案 Final 使用的數值範圍（MOBILE_SYNTAX §2、§7）。

速度的交付規則（MOBILE_SYNTAX §7）：在實機測試證明可以放寬之前，專案 Final 的交付規則是：

  1. 每個有內容的角色，開頭都寫同一個起始速度；
  2. 曲中換速度時，每個有內容的角色都帶同一張完整的速度表，換速度的位置在音樂上完全相同；
  3. 完全空白的角色維持空白，不為了通過檢查而塞速度或休止符；
  4. 這條「每個角色重複速度表」是為了保持同步的專案安全政策，不是在宣稱遊戲引擎技術上要求每個角色都寫速度。

只有一個角色帶曲中速度變化時，遊戲客戶端能不能保持同步，目前是 PENDING_IN_GAME（待實機驗證，PENDING P2）。

曲中換速度本身不違法，但有漂移的實際風險：來源、預覽與候選的速度表必須完全一致，換速度的位置要有來源依據，並做逐曲的時間驗證。重複寫一次「目前已經生效的速度」不改變任何時間，不算速度表的一部分。

照這條規則，一首三個角色、第二小節起從 120 換成 90 的曲子，三個角色都要在同一個位置寫：

MML@t120o4l4cdeft90gfed,t120o4l2cet90db,t120o3l1ct90g,,,;

工作坊專用：工作坊播放時，會把所有分頁（包括不會送進遊戲的輔助軌）寫的 t 合併成一張速度表：同一個位置有好幾個分頁都寫時，以分頁號碼小的為準；整首都沒寫時用 120。超出 32–255 的值會被夾進範圍。狀態列的「速度」欄會列出合併後的結果（例如 120 → 90）。

因為是合併後才播，工作坊裡就算只有一個分頁寫了 t，聽起來也是整首同步的——這只說明工作坊怎麼播，不代表遊戲會這樣處理（那正是 PENDING P2 待驗證的事）。

工具列的「速度」按鈕（「速度/拍速」視窗：設置位置選「音軌開頭」或「選擇的音符前」、輸入速度（BPM）、「試聽」、「移除這個速度記號」、「執行」）會把整張速度表寫進主旋律，並刪掉其他所有分頁的 t；其他分頁有音符跨過換速度的位置時，會在那裡切開再用連結線接回去。這樣做出來的譜只有主旋律帶速度，不符合上面的 MOBILE_SYNTAX §7 交付規則。交付前請讓每個有內容的角色都帶同一張速度表；送回 Studio 時，Studio 會把各角色速度表不一致列為問題（Final 驗證時是錯誤）。

力度

v 後面接數字決定音量，數字越大越響。官方範圍是 0–15（MOBILE_SYNTAX §2）。它跟 l 一樣是持續生效的——設了之後，後面所有音都用這個力度，直到下一個 v。

o4v12cdev8fga    前三個音較響，後三個較輕

多角色合奏時，伴奏角色調低幾格會讓主旋律浮出來。

工作坊專用：工作坊與 Studio 在沒寫 v 時都當成 v8。工作坊會把超出 0–15 的值夾進範圍，Studio 的解析器則把它當成錯誤。工具列的「力度」按鈕（「力度/音量」視窗，範圍可選「全部音軌」「目前音軌」「選擇的音符」）可以整段調整，不用一個一個改。

連結線與 n 指令

& 把前後兩個同音高的音接成一個長音：

c1&c1    連續兩個全音符長度的 Do，中間不斷開
  c1&c4    五拍長的 Do

跨小節的長音、長度表達不出來的拍子（例如五拍）、以及 Final 不允許的附點寫法，都靠它改寫。

連結線只用在同一個音的延續（MOBILE_SYNTAX §8、MASTER_RULES §7）：& 只能接起「同一個音高、在音樂上本來就是延續」的音。不要用它把兩次重複起音藏成一個長音，也不要用它跨過休止符。相鄰的重複起音不能被默默改成一個延音；語法最佳化必須保留每一個起音。

工作坊專用：工作坊遇到接到不同音高或接到休止符的 &，會不聲不響地忽略它（後面的音照樣重新起音）；Studio 的解析器把這種寫法當成錯誤。送回 Studio 時，工作坊會把它沒有真的接起來的 & 刪掉並附上提示。

n 後面接數字是數字音高，不受 o 影響，也不改變之後的八度狀態。手寫很少用得到，主要出現在工具產生的譜裡。

數字音高 Nxx（MOBILE_SYNTAX §5、PENDING P3）：社群作品確實在用，所以不能說遊戲不支援（輸入能力的證據等級是 COMMUNITY_VERIFIED）；但官方的範圍與客戶端保證都沒有文件。專案 Final 的標籤是「謹慎使用」：

  • 讀進歷史／社群／來源的 MML 時，保留 Nxx 事件原本的身分；
  • 能用一般音名乾淨表達同一個事件時，就換成一般音名；
  • 只有在這首歌／這個專案明確開啟數字音高輸出，而且有這首曲子的往返或實機驗證支持時，可貼上的 Final 才保留 Nxx。

n 的數字到底對到哪個音，目前還沒有定論。工作坊與 Studio 兩個解析器對同一個 n 的讀法差 12 個半音（一個八度）：工作坊把 n48 讀成和它的 o4c 同一個音，Studio 則把 n60 讀成和它的 o4c 同一個音。遊戲實際採用哪一種，還在等實機 A/B 比對，未經驗證，所以這一頁不把任何一種對應當成事實。

為了讓兩邊聽到、分析到的是同一個音，「從 Studio 開啟」與「送回 Studio 驗證」在交接時會改寫 n 的數值，其他文字不動；開啟時如果改寫過，狀態列會說明。在這個問題解決之前，想讓譜在各處讀起來都一樣，最穩的做法是用一般音名，不用 n。

工作坊專用：工作坊的 n 用目前的預設長度 l，也可以加附點；Studio 的 N 只吃 L 的長度、不能加附點（送回時帶附點的 n 會改寫成同音高、同長度的音名）。另外，「剪貼簿」→「複製」會自動做無損壓縮，為了省字可能把某些音寫成 nNN——這些數字是照工作坊的讀法寫的，在上面那個對應問題解決之前，貼到別處時音高可能差一個八度。

角色與字數上限

瑪奇 Mobile 的作曲最多有 6 個角色（基本 3 個，可擴充到 6 個，MOBILE_SYNTAX §2）：主旋律加和弦 1–5。其中主旋律、和弦 1、和弦 2 三個角色是單人演奏的核心（Core3），和弦 3–5 預設是加值（MASTER_RULES §5）。整首的字串把各角色用逗號分開，前面加 MML@、結尾加 ;；Studio 的 Final 與「送回 Studio 驗證」一律寫成六個軌位，空的角色就留空：

MML@t120o4l4cdef,t120o4l4ceg>c,t120o3l2cg,,,;

每個角色最多 2,400 個字，這是官方確認的上限（MOBILE_SYNTAX §2、§9）。遊戲客戶端到底怎麼數字元——跟 Python／JavaScript 的字串長度是否相同、會不會先正規化——仍待實機驗證（MOBILE_SYNTAX §9、PENDING P1），所以任何工具算出來的字數都不能說跟遊戲完全一致。

空的角色維持空白（MOBILE_SYNTAX §10）：不要為了通過檢查塞休止符或速度。客戶端對空的和弦軌位怎麼處理，也仍待實機驗證（PENDING P7）。

工作坊專用：

  • 工作坊開得出最多 15 個分頁：主旋律、和弦1–和弦5，以及輔助1–輔助9。只有前 6 個會進遊戲、會交給 Studio；「複製」與「送回 Studio 驗證」都只取前 6 個分頁，後面的是編曲時暫放素材用的。分頁的位置就是它的身分，拖曳分頁排序會連內容帶樂器一起搬。
  • 工作坊算字數時不含空白、換行與註解，所以在工作坊裡可以用換行分小節，讓譜好讀一點。「複製」會去掉空白；但 Studio 的解析器不接受角色裡有空白或換行，所以交付的字串裡不能有。
  • 某個分頁超過 2,400 字時，分頁上的字數會變紅（「設定」裡的「語法上色」啟用時，超出的那一段還會加紅底），但不會擋住你繼續編輯。要壓下來看常見問題那一節。
  • 「複製」出來的字串會省略結尾的空角色，所以不一定有六個軌位；「送回 Studio 驗證」則一律送六個。

工作坊、Studio 與其他工具的寫法差異

MML 不只瑪奇在用，各家實作的細節不完全一樣。下表左欄是工作坊目前的解析器怎麼處理（工作坊專用），右欄是 Studio 的解析器（studio/backend/mml/parser.mjs）接受什麼。工作坊為了讓從別處拿到的譜也讀得進來，比 Studio 寬鬆很多；Studio 讀不懂的寫法，送回時由工作坊改寫，改寫不了的會附上提示照送，由 Studio 回報。

工作坊專用：下表的「工作坊」欄描述的是編輯器的方言，不是遊戲規則；工作坊讀得進來，不代表遊戲或 Studio 讀得進來。

寫法工作坊Studio 解析器
大小寫當成同一個字當成同一個字
h當成 b（德式記法，3MLE 的譜偶爾會有）讀不懂，報錯；送回時改成 b
p當成休止符 r讀不懂，報錯；送回時改成 r
#當成 +接受，當成升記號；送回時仍改寫成 +
c++ 等連續升降記號逐一累加只接受一個升降記號；送回時改寫成單一拼法
@ 加數字的樂器指令演奏時不生效，音色由分頁上的樂器決定；用「剪貼簿」→「貼上」整首貼入時，每個角色的第一個 @n 會用來替那個分頁挑樂器（對得上時），然後從文字裡拿掉讀不懂，報錯；送回時拿掉
[ceg]4 和弦不支援。[ 與 ] 被當成看不懂的字元（狀態列警告）並略過，裡面的音名照單音依序讀——舊譜的和弦會變成旋律讀不懂，報錯；送回時拿掉看不懂的字元
註解 /* … */、// …略過，不算字數讀不懂，報錯；送回時拿掉
角色裡的空白、換行略過，不算字數報錯（角色必須是純 MML 字串）；送回與複製時拿掉
單一分頁裡的逗號狀態列提醒要分軌請改用「貼上」；逗號兩邊的內容會接在一起讀逗號是角色分隔符號
MML@ 前綴與結尾的 ;貼進單一分頁也沒關係，會自己處理掉（; 之後的內容不讀）整首驗證時必須是從 MML@ 到 ; 的完整字串，而且剛好六個軌位
第一個音名前沒寫 o從 o4 開始報錯；送回時補上 o
雙附點 c4..1.75 倍讀取時保留並警告，Final 驗證時是錯誤；複製與送回時工作坊先改寫成等長的單附點加連結線
帶附點的預設長度 l4.支援（見長度與附點）讀不懂，報錯；送回時改成 l4 並把長度寫在音上
接到不同音或休止符的 &略過，不警告報錯；送回時拿掉並提示
超出範圍的 t、v夾進 32–255、0–15報錯；送回時工作坊先夾好
超出範圍的音高摺進 o1c–o7b 播放並警告實作對應是 O0–O8；換算後超過 107 的音名會警告
n 數字音高讀法見上面，和 Studio 差 12 個半音讀取時警告為謹慎語法；Final 需要明確開啟與驗證證據；交接時 n 的數值會被改寫

工作坊專用：「剪貼簿」→「複製」除了去掉空白、只取前 6 個分頁之外，還會自動做無損壓縮（音符完全相同，只換寫法）。為了省字，壓縮出來的文字可能省略開頭的 o4、改用 b+／c- 或 nNN 這類寫法，也可能用 3、6、12、24、48 這些長度與它們的附點形式。這些都不是 Canonical Final 的預設寫法；要交付的譜，請送回 Studio 驗證。

最常見的錯誤

  1. 只在一個角色寫 t——照 MOBILE_SYNTAX §7，每個有內容的角色都要從同一個速度開始，換速度時都帶同一張速度表。工作坊播放時會把速度合併，所以在工作坊裡聽不出問題；遊戲在只有一個角色帶速度變化時能不能同步，還沒有驗證。
  2. 用了帶附點的預設長度或雙附點——l4. 是工作坊的方言，Studio 不收；4.. 這類多附點在 Final 裡是禁止的，要改寫成等長的音符＋連結線。
  3. 以為 [ceg] 和弦寫法還能用——不能，那三個字母會被當成三個依序的音。真正的和弦要拆到不同角色。
  4. 用 & 接不同的音——連結線只用在同一個音的延續，不能跨休止符，也不能拿來把重複起音藏成長音。
  5. 只算字數不算角色——2,400 是每一個角色的上限，不是整首的；遊戲實際怎麼數字元仍待驗證，別把譜壓到剛好 2,400 字的邊緣。

想直接把現成的曲子變成 MML，不用一個音一個音打——看 MIDI 轉 MML。其他問題看常見問題。
