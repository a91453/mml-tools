# History Audit — back number〈瞬き〉

## Current accepted

**v29R** is the current accepted version.

Latest user device/listening conclusion:
> 「V29r好了 如果同聲的樂器變厚好像有點雜 不同樂器還好」

This supersedes the temporary TL1 / TL1+C acceptance sequence. The present practical reason is not “lower overlap count = automatically better”; it is the user's whole-song target-client preference for v29R's cleaner same/similar-instrument texture.

## Curated milestone history

### v13 — original-pitch/source-faithful historical reference
Early reference preserving the main source roles with minimal Mobile adaptation. Later used as an important version-drift zero point. Historical liking of v13 is **not** source truth.

### v20 — source/audio-first repair
Important restoration: missing rapid Bass source onsets were restored. This was a source-completeness correction that survived into later Bass note counts.

### v23 — important in-game cleanup milestone
Chord3 retreat windows around beats 179–182, 378–383, and 433–435 were followed by explicit user feedback:
> 「明顯好太多了」

This remains strong song-specific in-game evidence for reduced prominence/voice allocation in those windows.

### v24–v27 — incremental arbitration
Additional inner-voice retreats, register/voicing decisions, and Core3 redistribution were introduced. These versions increased drift gradually but preserved Melody.

### v28 aggressive — rejected
Multiple source voices were restored at once. This made attribution weak and increased interaction risk. It was rejected as an overly broad change set.

### v28 conservative — constrained repair
Only a small set of known artificial re-entry/continuity problems were repaired. This became the safer base for v29 arbitration.

### v29 / v29R — paired arbitration and current accepted lineage
v29 introduced focused cross-source decisions such as the 207–213 paired arbitration and 853–855 Core3 redistribution. v29R is byte-identical to v29 and was revalidated under Published Canonical.

### SF6R — Source-Faithful six-track reduction reference
Built as a bridge between the event-level Source-Faithful Baseline and Mobile Final. It restored fuller source roles and became an A/B reference. The user initially preferred it to v29R:
> 「我覺得你的變得比最終版好聽了」

That feedback reopened the over-clean hypothesis, but did not permanently replace v29R.

### TL1 — prominence-only experiment
TL1 preserved SF6R pitch/onset/duration identity and only reduced three Chord3 logical-note volumes. User feedback:
> 「有提升」

This established that prominence control could improve the fuller reference without deleting source note events.

### TL1+C — temporary acceptance, then rejected
TL1+C added two register changes:
- Bass 711–717: D#2 → D#3
- Chord1 1047–1053: D5 → D4

It was first described as:
> 「tl1+c很完美」

Then explicitly overturned:
> 「沒有不改比較好聽 被推翻了」

This rejects the **combined C bundle on TL1**. It does not isolate which individual register change caused the preference.

### Return to v29R — final choice
After more whole-song comparison:
> 「最後還是覺得v29r比較乾淨一點」

Then:
> 「V29r好了 如果同聲的樂器變厚好像有點雜 不同樂器還好」

This is the latest explicit accepted state and therefore the current package Final.

## Known regression / drift lessons

- A historical blind first-identical-text replacement changed the wrong Chord3 occurrence. Event-position parsing/readback is required after edits.
- “Newer” and “more source notes” did not guarantee better Mobile playback.
- The over-clean hypothesis was useful to test, but it was **not confirmed as a current defect** after final whole-song comparison.
- v29R's extra cleanup can sound cleaner, while TL1/SF6R can sound fuller. Both observations are real; the accepted decision is song/setup-specific.

## Rollback conclusion

No rollback is currently requested or justified. v29R is the current accepted version. SF6R/TL1 remain historical A/B references.
