## How it was produced

1. **Build and publish.** [Release run 35838230641](https://github.com/a91453/mml-tools/actions/runs/35838230641) was dispatched while `origin/main` was exactly the source SHA.
   - CI rebuilt the same buildId, and the verifier returned `ARTIFACT_VERIFIED`.
   - The committed lock was byte-identical (`cmp`), and the run ended with `DURABLE_RELEASE_PUBLISHED`.
2. **Mirror to the bucket.** [Mirror run 35840521224](https://github.com/a91453/mml-tools/actions/runs/35840521224) uploaded both ZIPs to bucket `studio-release-artifacts` at the lock's object keys.
   - It then read each object back and matched its SHA-256 (`DURABLE_MIRROR_VERIFIED`, `uploaded: true`).
   - The bucket credentials were temporary repository secrets.
3. **Local proof under Bun.**
   - The rendered function started the new release from a verified cache, and `/health` reported this buildId and source.
   - A copy with one character changed exited with `RENDERED_SOURCE_MISMATCH` before doing anything else.
4. **Deploy.** The function source was replaced with Railway's function-code operation. This created new deployment `4e5d6a8b-052c-4372-a3e0-e1d98fffa40f` from the current configuration; variables, volume, image and healthcheck were unchanged.
   - The deployment passed the `/health` healthcheck and reached `SUCCESS`.
   - The previous deployment `9ddaad2c-fc64-4822-a011-3924e3aae629` became `REMOVED`.
