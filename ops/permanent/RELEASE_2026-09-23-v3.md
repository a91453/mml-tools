## How it was produced

1. **Build and publish.** [Release run 35929382025](https://github.com/a91453/mml-tools/actions/runs/35929382025) was dispatched from the ops branch while `origin/main` was exactly the source SHA.
   - CI rebuilt the same buildId, the committed lock was byte-identical (`cmp`), and the run ended with `DURABLE_RELEASE_PUBLISHED`.
2. **Mirror to the bucket.** [Mirror run 35929471358](https://github.com/a91453/mml-tools/actions/runs/35929471358) uploaded both ZIPs to bucket `studio-release-artifacts` at the lock's object keys and read each back (`DURABLE_MIRROR_VERIFIED`, `uploaded: true` for both).
3. **Local proof under Bun** (before deploying).
   - `ops/permanent/bootstrap.test.mjs` passed 2/2 against these assets.
   - A cache seeded from the runtime ZIP ran the full chain, and `/health` reported this buildId and Canonical v3.
   - The rendered function (rendered twice, identical) then started offline from that cache: `RENDERED_SOURCE_VERIFIED` → `TRUSTED_SOURCE_VERIFIED` → `ARTIFACT_VERIFIED` → `VALIDATED_CACHE_STARTUP` → `SERVER_STARTED`.
   - A copy with one character changed exited with `RENDERED_SOURCE_MISMATCH`.
4. **Deploy.**
   - The function source was staged with Railway's function-code operation and read back; its SHA-256 equalled the rendered file.
   - Committing the staged change through the API timed out three times without creating a deployment, so the owner committed it from the Dashboard.
   - The deployment reached `SUCCESS`; the previous deployment (the v2 release) became `REMOVED`.
   - No cache existed for this buildId, so it started from the durable source.

## Rollback

- The previous release cache `durable-v1/dd273bee…` stays on the volume, so rollback starts from cache without downloading.
- **R1:** render the function from the ops files at commit `e8d7a998d926744450d477402a544ca03e9c044a` (the v2 lock; `build_function.py`) and replace the function source with it; that creates a new deployment. Expect `VALIDATED_CACHE_STARTUP` with `refetch: false`.
- **Alternatively:** in the Dashboard's deployment history, roll back to the deployment this release replaced.
- Never delete cache namespaces, bucket objects, Releases or tags.
